Move the Overview refresh out of the Overview tab

Strong in-process

Before

After

Problem
The refresh is a callback slot that the Overview tab's constructor fills (state.Refresher = RefreshAsync). Every caller inherits a widget rebuild and its failure modes, and has to pick one of three entry points, each with different null behaviour.
Solution
Make OverviewState the deep module. It owns the Blocking gather, the rule that a partial report becomes current on failure, and the log line. The tab subscribes to Report and rebuilds its frames.
Wins
  • Deletes the Refresher slot and AppSession's pass-through
  • Removes the Scanner's catch for a frame rebuild
  • Scanner tests stop building an OverviewTab
  • Locality: the partial-report rule lives in one place
  • Leverage: one interface for three callers

Problem
The #94–#101 sweep made Handle the way into a UI Action, but each caller still builds the rest of the flow by hand: 8 Run* calls, 5 OperationFailedException catches, 2 hand-held blocks, and 3 ways of getting progress back to the UI thread. The ordering rules exist only in comments, repeated in 4 files.
Solution
One runner entry point takes the phase, the work and a progress sink, and returns the result or a typed partial result. It owns the busy flag, the block span and the marshalling.
Wins
  • Interface shrinks from 9 rules to 3 parameters
  • Locality: ordering rules in one module
  • Fewer DispatcherWait polls in tests
  • Catches the remaining _ = ShowModalAsync sites
ADR-0003 stands: every operation stays Blocking or Interactive. This candidate puts that rule behind one interface; it doesn't revisit the rule.

DowngraderRunTests (30 tests)

Two adapters: a real seam. Its interface gets narrower and stops encoding failures as bools.

Problem
The window builds volatile mirrors of the boxes, an Interlocked operations counter, a Dispatcher.Post poll and an event switch. The phase contract is split: the App picks the poll's first phase, and Core reports the switches after it. The rule for resolving NextGenAndAnniversary (DG-3) sits on the window.
Solution
Core owns the whole run, including the poll's starting phase and the in-flight state. The host only provides an options read, a refresh that throws, and a way to run an operation. Version labelling moves into Core.
Wins
  • Deletes the bool translation and the private exception
  • Moves DG-3 into Core, where it can be unit-tested
  • The window keeps rendering only
Simpler after 01 and 03: the refresh and the runner then have one interface each to call.

Let the Overview report own its problems and verdicts

Before

After

Problem
Five files append to one mutable list. The problem order is a contract, but you can only see it by reading the call order. The Scanner borrows Overview's AddSimple. The MO2 Windows 11 warning and the MO2 details text are decided in the tab and tested only by clicking through the About window.
Solution
Each gathering returns its problems, and Gather owns the order. The verdicts the tab computes become fields of the report. The problem kinds come together in one catalogue.
Wins

  • MO2/Win11 rule gets unit tests
  • Scanner stops depending on Overview internals

Top recommendation

01 · Move the Overview refresh out of the Overview tab

It is the smallest change, and #96 just changed this path. It removes the coupling that forces every Scanner, Downgrader and Archive Patcher test to build an Overview tab. It also clears the way for 02 and 04: both then call one refresh interface instead of a tab's widget-rebuilding method.
